# AutoExcal 迁移 Prompt

## 1. 背景

当前项目中的 `parts/page/page_autoexcalpage.py` 是一个基于 PyQt5 / siui 的页面，核心功能是：

1. 导入主 Excel 表格
2. 导入待插入 Excel 表格
3. 从原始表格提取“姓名 / 学号 / 分数”三列
4. 支持默认提取模式与自定义坐标提取模式
5. 支持手动插入、批量插入、删除最终数据
6. 将最终数据保存为 `data.json`
7. 打开浏览器并登录目标系统
8. 分批将成绩自动录入网页表单
9. 记录录入进度，支持继续下一批

当前实现把 UI、Excel 读取、数据转换、JSON 持久化、浏览器自动化、线程控制全部耦合在一个页面文件中，因此不利于迁移到其他库。

---

## 2. 现有核心逻辑总结

### 2.1 页面职责

`Autoexcal` 页面本质上是一个：

**“Excel 数据清洗 + JSON 持久化 + 浏览器自动批量录入”** 的工具页。

### 2.2 关键状态

页面维护的核心状态包括：

- `self.sheet`：主 Excel 工作表
- `self.new_sheet`：第二个 Excel 工作表
- `self.browser`：浏览器实例
- `self.last_tab`：当前网页 tab
- `self.main_loop_thread`：录入线程
- `self.index_current_data`：当前录入进度
- `self.data`：从 `data.json` 读取出的最终数据

### 2.3 数据流

#### 主表流程

- `import_file_for_table_widget()`：导入主 Excel
- `reload_data_for_new_table_widget()`：提取姓名 / 学号 / 分数到最终表
- `save_to_json()`：保存最终数据到 `data.json`

#### 候选插入表流程

- `import_file_for_new_table_widget()`：导入待插入 Excel
- `reload_data_for_new_table_widget()`：提取候选数据到 `new_insert_table_widget`
- `insert_new_data_for_new_table()`：把候选数据插入最终表

#### 自动录入流程

- `open_broswer()`：启动浏览器并登录系统
- `start_main_loop_in_thread()`：开启线程
- `MainLoopThread.run()`：每批写入最多 49 条数据到网页输入框

## 3. 现有业务规则

迁移时必须保留以下业务行为：

### 3.1 最终数据结构

每条最终数据至少包含：

```json
{
  "unique_id": 0,
  "name": "张三",
  "stu_id": "2023303010001",
  "score": "3"
}
```

### 3.2 默认提取规则

当未启用自定义输入时：

- 从第 9 行开始读取
- 第 5 列为姓名
- 第 6 列为学号
- 第 7 列为分数

### 3.3 自定义提取规则

当启用自定义输入时：

- 用户通过 `(row,col)` 输入起始 / 结束坐标
- 分别提取姓名、学号、分数三段区域
- 组合成统一三列表结构

### 3.4 空行处理

提取后需要删除三列都为空的行。

### 3.5 最终数据编辑

必须支持：

- 输入框手动插入 1 条数据
- 从候选表批量插入多条数据
- 删除最终表中的选中行

### 3.6 持久化规则

最终表内容统一保存到 `data.json`，供自动化模块读取。

### 3.7 批量录入规则

网页一次最多录入 **49 条** 数据。

字段映射规则：

- 学号输入框：`txtstu1 ~ txtstu49`
- 分数输入框：`txtpoint1 ~ txtpoint49`

### 3.8 断点续传规则

通过 `index_current_data` 记录当前已完成位置，支持继续下一批录入。

## 4. 当前代码中的已知问题

迁移时不要直接照搬这些缺陷：

1. `open_broswer()` 中使用了未定义的 `self.choose_boswer_sw`
2. `MainLoopThread.stop()` 直接调用 `terminate()`，停止方式不安全
3. `save_to_json()` 使用 `names.index(name)` 生成 `unique_id`，遇到重名会出错
4. `delete_data_for_table_widget()` 删除的是相对路径 `data.json`，而读写 JSON 用的是脚本目录路径，路径不一致
5. `main_loop()` 中把 `self.last_tab` 赋值为字符串后又调用 `.ele()`，逻辑错误
6. `insert_data_for_new_table()` 中保留了无意义的 `pass`
7. 业务逻辑直接读写 `QTableWidget`，与 UI 强耦合
8. Excel 读取、数据清洗、JSON、自动化、线程控制全部写在页面类里，不利于维护和测试

## 5. 目标迁移方向

如果没有明确指定目标库，请按照下面的思路迁移：

### 5.1 优先目标

先把系统重构为“业务逻辑与 UI 解耦”的架构，再接入新的 UI / 自动化库。

### 5.2 推荐分层

#### A. UI 层

职责：

- 展示表格
- 收集用户输入
- 触发命令
- 展示提示信息

可替换为任意目标库，例如：

- PySide6
- Tkinter
- Flet
- Web 前端

#### B. Excel / 表格转换服务层

职责：

- 读取 Excel
- 按默认规则提取数据
- 按自定义坐标提取数据
- 清理空行
- 合并 / 插入 / 删除数据
- 去重

要求：

- 仅使用普通 Python 数据结构
- 不直接依赖 `QTableWidget`

#### C. 持久化层

职责：

- 保存 JSON
- 读取 JSON
- 统一管理文件路径

#### D. 浏览器自动化层

职责：

- 启动浏览器
- 登录 VPN / 门户 / 教务系统
- 跳转到目标页面
- 按批次录入成绩
- 支持从指定偏移继续

#### E. 任务调度层

职责：

- 后台执行批量录入
- 报告进度
- 支持安全停止

---

## 6. 迁移要求

1. **保留现有业务语义，不要改动用户能感知到的核心功能**
2. **不要把业务逻辑继续写死在 UI 控件里**
3. **所有核心逻辑应尽量可单元测试**
4. **JSON 路径管理必须统一**
5. **去重逻辑应按更可靠的键实现**，优先考虑：
   - `stu_id`
   - 或 `(name, stu_id, score)`
6. **停止后台任务时不能使用粗暴终止方式**，应改为协作式停止
7. **浏览器自动化部分应保留可替换接口**，避免再次和某个具体库强绑定
8. **提取逻辑要兼容默认模式与自定义坐标模式**
9. **自动录入仍需遵守每批 49 条的约束**
10. **最终输出结构应清晰，便于后续继续接入其他库**

---

## 7. 验收标准

迁移结果至少满足：

1. 可以从 Excel 中读取原始数据
2. 可以按默认规则生成最终三列表
3. 可以按自定义坐标生成最终三列表
4. 可以删除空行
5. 可以手动插入 / 候选插入 / 删除最终数据
6. 可以稳定保存并读取 JSON
7. 自动化模块可以按批次读取 JSON 并完成网页输入
8. 可以从中断位置继续下一批
9. 停止任务时不会强制杀线程导致不一致状态
10. UI 层替换时，不需要改动核心业务代码

---

## 8. 建议实施顺序

### 第一步：抽离纯业务逻辑

先把以下逻辑从页面类中独立出来：

- Excel 读取
- 默认提取
- 自定义提取
- 空行清理
- 数据插入 / 删除 / 合并
- 去重
- JSON 持久化

### 第二步：抽离自动化服务

把以下逻辑单独封装：

- 启动浏览器
- 登录 VPN
- 登录门户
- 进入目标业务页
- 按批录入数据

### 第三步：抽离后台任务控制

把线程 / 协程 / 任务队列的控制改为独立任务层。

### 第四步：重写 UI 适配层

使用目标库重写界面，但只调用服务层接口，不在界面中直接写业务逻辑。
